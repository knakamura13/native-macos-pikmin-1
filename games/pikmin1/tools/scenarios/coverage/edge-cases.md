# Scenario inventory: edge cases, state machines and invariants

Slice owner: edge cases, state machines, invariants. All paths are under `games/pikmin1/` unless noted.
Inventory from code. Every `file:line` pointer was checked against 3c7d100b (after the kyle-develop merge) and carries its function name, the stable pointer if a number drifts. Rows marked "verified" were run in the scenario harness (log in [README.md](README.md)); the rest are read-only findings.

## 0. Harness facts that shape every row

- Scenario API: `PcScenario` (`pc_port/scenarios/pc_scenario.h`): `startDay`, `onStageReady`, `providePads(tick, pad0)`, `onTick(tick)`. Pad 0 only, pads 1-3 neutral. Runner calls `sScenario->onTick` at `pc_scenario.cpp:404 (pc_scenario_on_tick_end)` (after the intro gate, so tick 0 has the captain in Walk).
- Spawning recipe (copy from `scenario_throw_release.cpp:82-100 (ThrowRelease::spawnSquad)`): `pikiMgr->birth()`, `GameStat::workPikis.inc(color)`, `piki->init(navi)`, `piki->Creature::init(at)`, `piki->initColor(color)`, `piki->changeMode(PikiMode::FormationMode, navi)`, `GameStat::update()`. A scenario must do the GameStat bookkeeping itself, as the game's own spawners do (`generator.cpp:1151 (GenObjectPiki::birth)`, `gameCoreSection.cpp:1750 (pcVsSetupBases)`).
- Damage can be injected with no enemy asset: `piki->stimulate(InteractAttack/Fire/Flick/Bubble/Swallow/Press/Kill/Bomb ...)` and `navi->stimulate(InteractFlick/Bury/Bubble ...)` (`interactBattle.cpp:33-556 (InteractBomb::actPiki)`, `navi.cpp:4466-4760`). This is the cheapest way to cover hazard death paths on STAND-IN tier. Needs the effect/particle stand-ins to exist (`EffectMgr` calls in `Piki::startFire`, `pikidoKill.cpp:100 (Piki::doKill)`); objects_smoke already boots effects, so likely fine.
- Settings: scenarios run with settings neither read nor written. Scenario setters: `pc_settings_scenario_set_infinite_day`, `..._set_fps_mode` and `..._set_whistle_pluck` (onion_unlock_whistle) (`pc_settings.cpp:9023-9026 (pc_settings_scenario_set_*)`). Every PC-port-departure row below (quick grab, throw speed, chain actions, invincible Pikmin, Pikmin limit, navi/teki health pct, whistle radius) needs one new `pc_settings_scenario_set_<x>` setter each (pattern: `sScenarioSettings` branch in the getter, `pc_settings.cpp:8979-8995 (pc_settings_get_fps_mode, scenario branch)`). Effort S each. The Pikmin cap can instead be set directly with `AICONST.mMaxPikisOnField(n)` (`gameCoreSection.cpp:2863 (GameCoreSection::initStage)`), but `pikiMgr->create(limit+2)` sizes the pool at stage load (`gameCoreSection.cpp:2227 (GameCoreSection::initStage)`) and `CPlate` slots at `pc_settings_get_piki_limit()+10` (`cPlate.cpp:43`), so lowering is safe, raising is not.
- Stand-in stages today: `sandbox` (flat floor, one cliff), `sandbox_objects` (cliff, blue Onion, 3 sprouts, 1 red pellet, 1 sleeping Dwarf Bulborb), `sandbox_all_objects` (soft gate, 6 plants, 2 bridges, push box, 2 bosses, 8 enemies; only boot-smoked). No water attribute triangles, no fire/bomb/electric sources, no geyser, no cave hole, no ship parts known to exist (verify in `tools/scenarios/standin_*_stage.h`).
- Tier meaning: STAND-IN = runs in CI on generated assets. DISC = needs the real install (real enemy AI, real terrain, real parms). "STAND-IN+" = stand-in tier but needs the named extra stand-in asset.
- Extinction trigger (important for EC-10..13): `gameCoreSection.cpp:3388 (GameCoreSection::update)` fires `NAVISTATE_PikiZero` when `GameStat::allPikis == 0 && GameStat::maxPikis > 0`. **Verified composition of `GameStat::allPikis`** (`GameStat::update`, `gameStat.cpp:66-81`): per colour, `mapPikis = formationPikis + freePikis + mePikis + workPikis` and `allPikis = mapPikis + containerPikis`. So it counts Pikmin in the field in any mode, sprouts in the ground (`mePikis`, raised in `PikiHeadItem::startAI`, `pikiheadItem.cpp:144`, as soon as a seed starts its AI) and Onion contents (`containerPikis`, seeded at stage start from `pikiInfMgr` totals in `GameCoreSection::initStage`, `gameCoreSection.cpp:2617-2619`, then set from each Onion's `mHeldPikis` in `GameCoreSection::finalSetup`, `gameCoreSection.cpp:2655-2660`). It does not count the dead: `Piki::doKill` raises `deadPikis` and lowers `workPikis`. Removing a sprout with `kill()` does not lower the total either: `PikiHeadItem::doKill` (`pikiheadItem.cpp:169-176`) moves it from `mePikis` to `workPikis`, as a pluck does. Stand-in run (sandbox, 3 blue in Formation): killing the three left `all` at 0 and triggered PikiZero on the next tick; with one sprout planted, killing the last field Pikmin left `all 1` (`me 1`) and the captain stayed in Walk for 5 s. On the disc's Forest of Hope a stage sprout exists at start (`me 1`) and blocked extinction the same way. Then `naviState.cpp:3470 (NaviPikiZeroState::exec)` posts `MOVIECMD_GameEndCondition/ENDCAUSE_PikminZero`, handled at `newPikiGame.cpp:3316-3347 (GameMovieInterface::parse)` (first hit: sets `flowCont.mGameEndFlag = GAMEEND_PikminExtinction` and plays demo46; the second hit comes from demo46's own Notify key at frame 167 and plays ExtDayEnd and sets the clock to `mEndHour`; ExtDayEnd's `ForceResults` key then clears the flag and the day end follows; on day 30 or challenge mode the flag is reset instead). Full traces: `terminals.md` T04.
- Suspected latent bug worth pinning (EC-33): `gameCoreSection.cpp:3367 (GameCoreSection::update)` sundown warning guard `(mGameEndFlag != PikminExtinction || mGameEndFlag != NaviDown)` is always true. Decomp-original, so GameCube fidelity: keep, only characterise.
- Suspected quirk worth pinning (EC-04): `itemAI.cpp:908 (GoalAI::EmitPiki::act)` (`GoalAI` exit path) increments `bornPikis` before checking whether a seed could be born; when the field is full the Pikmin stays in the Onion (`:925 (GoalAI::EmitPiki::act)`). So `bornPikis` counts attempts, not sprouts, at the cap. Original behaviour, characterise only.
- Caveat: apart from the rows marked verified (EC-06, EC-10, the `allPikis` composition above), these are static-read findings, not run results.

## 2. Generic invariant checkers (run in every scenario)

Hook: add one function `pc_scenario_check_invariants(tick)` called in `pc_scenario_on_tick_end` right before `sScenario->onTick` (`pc_scenario.cpp:404`) and also during the intro gate. It must call `scenarioFailf` with a named invariant. It is free: no new assets, pure reads of `pikiMgr`, `naviMgr`, `GameStat`, `gameflow`. Each can be disabled per scenario by a `virtual bool invariantsEnabled(unsigned mask)` for the few that purposely break one (EC-05 negative control).

| Id | Checker | Predicate | Why it is safe |
|----|---------|-----------|----------------|
| I-1 | Finite, sane positions | for every Navi, Piki, Teki, Pellet, item in the managers: `isfinite(mSRT.t.x/y/z)`, `isfinite(mVelocity)`, `abs(coord) < 1e6`, and `mHealth` finite | NaN poisons the state hash and netplay; catches sim blow-ups at the tick they happen. |
| I-2 | GameStat vs live lists | per colour: `workPikis+formationPikis+freePikis` equals the count of alive `Piki` of that colour in `pikiMgr`; `mePikis` equals the count of live `OBJTYPE_Pikihead` items; no `ColCounter` entry < 0; `allPikis == mapPikis + containerPikis`; `maxPikis >= allPikis` | Directly guards the quiet accounting bugs above (EC-05/06). Run first in disc mode to find baseline mismatches before turning it to hard fail; known sources of off-by-one (a Pikmin mid-Emit/Enter) need a whitelist by state id. **Implemented** (counter and live-Pikmin checks; `mePikis` vs live sprout items not checked, no whitelist was needed: all existing scenarios pass).|
| I-3 | Caps respected | `GameStat::mapPikis (+ onion exit) <= AICONST.mMaxPikisOnField() + 1`; live Piki count `<= pikiMgr` pool size; plate: `getPlatePikis() <= limit` | Catches limit-setting regressions without a dedicated test. |
| I-4 | State/parent coherence | every alive Piki has a valid `getState()` in `[0, PIKISTATE_Count)`; `Hanged/WaterHanged/GoHang` implies `mNavi != null` and the Navi is in Throw/ThrowWait; `FormationMode` implies `mNavi != null` and a plate slot; `Dead/Dying` implies not in plate; every Navi state in `[0, NAVISTATE_Count)` | The "Hanged with no holder" and stale plate pointer class. |
| I-5 | Clock and pause monotonic | `gameflow.mWorldClock.mTimeOfDay` never decreases within a day (day number never decreases) outside a movie that sets the clock (extinction ExtDayEnd jumps forward only); while `mPauseAll` is true the clock and every Piki position stay unchanged | Catches clock rewind and "paused world still simulates". ## 3. Ranked first scenarios for this slice

1. `invariants_baseline` (I-1..I-5 wired into the runner, plus a one-off scenario that deliberately corrupts a counter to prove I-2 fails). Effort S-M. Every later scenario gains the checks for free, and it finds real accounting bugs early.
2. `pikmin_extinction` (EC-10, EC-11, EC-13): spawn, kill all via InteractKill, assert PikiZero, the end flag, the day end, and that Onion-held Pikmin block it. The owner named extinction explicitly; stand-in tier on the plain sandbox.

4. `piki_hazard_deaths` (EC-22, EC-23, EC-26, EC-27, EC-55): table-driven injection of Attack/Fire/Press/Flick/Bubble, correct state ids, colour immunity, counter bookkeeping, then invincible on. Needs no new assets.

8. `quick_grab_and_throw_speed` (EC-53, EC-54, EC-43): extend the `throw_release` K measurement with each setting on; one new setter per setting.
