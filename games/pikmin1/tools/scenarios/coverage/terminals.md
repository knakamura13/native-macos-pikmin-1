## 1. Flow map (what a scenario sits inside)

Section level (`GameFlow::softReset`, `src/plugPikiColin/gameflow.cpp:~748-790`): `SECTION_NinLogo`, `Titles`, `MovSample`, `OnePlayer`, `PaniTest` (`GameCourseClearSection` on PAL only), `OgTest`. `mNextGameSectionID` / `mCurrGameSectionID`.

OnePlayer sub-section level (`OnePlayerSection::init`, `src/plugPikiColin/game.cpp:264-489`): `GameSetup`, `CardSelect`, `MapSelect`, `E3Tutorial`/`E3ForestDay1`/`E3ForestDay2` (E3 leftovers, re-queue `NewPikiGame`), `IntroGame`, `NewPikiGame`, `GameCourseClear` and `GameStageClear` (comments say never hit), `GameCredits` (E3 demo only), `GameExit`. Selected by `gameflow.mNextOnePlayerSectionID`.

Inside `NewPikiGame` the mode states (NPG): `IntroGameModeState` -> `RunningModeState` (`:1041`) -> `MessageModeState` (extinction / captain down, `:1494`) and/or `DayOverModeState` (`:1608`, phases 0-4 at `:1869 / :1969 / :2107 / :2177`) -> `QuittingGameModeState` (`postUpdate` sets `gameflow.mNextOnePlayerSectionID = mParentSection->mPendingOnePlayerSectionID`, then `gsys->softReset()`).

Ending types: `ENDING_None/Neutral/Happy` (`include/FlowController.h:14-16`), `flowCont.mEndingType`. Written at NPG `:1134` (neutral, sunset on Day 30 with >= 25 parts), `:2071` (neutral, phase two), `:3418` (`MOVIECMD_SpecialDayEnd`, happy). Reset to `ENDING_None` in `gameSetup.cpp:188` and `movSample.cpp:~428`. Read by `GameExitSection::update` (`src/plugPikiColin/gameExit.cpp:32-47`): `!= None` goes to `SECTION_MovSample` with `mCurrIntroMovieID = mEndingType + MOV_ENDING_OFFSET (3)`, else `SECTION_Titles`. So the bad ending (no `mEndingType` write) returns to the title and neutral/happy go to the credits movie.

Game-end flag (`flowCont.mGameEndFlag`: `GAMEEND_None/PikminExtinction/NaviDown/Clear`, `include/FlowController.h:23-26`).

Constants: `MAX_DAYS = 30`, `MAX_UFO_PARTS = 30` (`include/GlobalGameOptions.h`), `happyEndable()` = `mRequiredUfoPartCount >= MIN_HAPPY_END_PARTS` (`src/plugPikiKando/playerState.cpp:328`; 25 per the code comment).

## 2. Harness facts that decide tiering

- Scenario ends the process on verdict. After a day-end completes, `QuittingGameModeState::postUpdate` calls `gsys->softReset()`, which builds `MapSelectSection` / `CardSelectSection` / `GameExitSection` -> `Titles`/`MovSample`. The stand-in tree has no map, file-select or title screens, so a scenario must pass or fail BEFORE that softReset. Needed harness addition (effort S): a `pc_scenario_on_soft_reset()` hook (in `QuittingGameModeState::postUpdate` or at the top of `GameFlow::softReset`) that hands the scenario `mParentSection->mPendingOnePlayerSectionID`, `flowCont.mEndingType` and `gameflow.mNextGameSectionID`, and for scenarios lets it pass without building the next section. Every "next section" assertion below depends on this.
- `MoviePlayer::startMovie` (`src/plugPikiColin/moviePlayer.cpp:431`) looks the movie up in the static `movieTitles` table, so every DEMOID is known; the `.cin` for it must then be opened (`info->initCore`). Whether a missing `.cin` aborts or is tolerated was NOT verified. Day-end phases wait on `gameflow.mMoviePlayer->mIsActive`, so with a tiny stand-in `.cin` (the `cinema.h` writer produces these) each phase advances in a few ticks. Stand-in cinemas today: demo60, demo61, demo41, demo45, demo04, demo06 only (`tools/scenarios/standin-cinema.md`). Extinction is `DEMOID_Extinction` (46) and `ExtDayEnd` (47, translated per stage); neither is in the tree (demo60 is `Unk60Cat`, a different movie).
- Stand-in `.blo` screens exist for: `gameover`, `gameove2`, `pause`, `pause_ok`, `count`, `con01`, `sund`, `account`, `play09/10`, `play_day`, `tu_base`, `wait_char`, `tu_tx00/03/20/26/35/37_*` (`libs/nectar_assets/src/standin_ui.cpp`). NOT present: results diary pages (`re_a_00` ... in `src/plugPikiOgawa/ogResult.cpp:38+`), total-results window, challenge result (`DrawCMresult`), file-check/select screens, world map. `TUT_BadEnding` text screen is not in the list (`tu_tx35` may be it; unverified).
- Existing scenarios cover none of the terminals except: `day30_clock` reaches `mIsDayEndActive` on Day 30 and then passes (clock/day-end start only). All scenarios boot through the intro gate (`IntroGameModeState` -> `RunningModeState`), so that transition is covered implicitly.
- `PC_SCENARIO` rejects `--mission-map`, `--vs-map`, `--coop*`, `--campaign`, `--input-replay` (`kRejectedFlags`, `pc_scenario.cpp:110`). Mission/VS/coop terminals therefore cannot run as scenarios without lifting that rule; see the notes in the table.
- Direct state manipulation available to a scenario: `gameflow.mWorldClock.setTime()/mCurrentDay` (used by `day30_clock`), `playerState` part counters (`mCurrParts`, `mRequiredUfoPartCount`), `pikiMgr` / `naviMgr` objects, `GameStat::*` counters, `gamecore->forceDayEnd()`, `flowCont.mGameEndFlag`.
